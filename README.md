# Переведення між проєктами

Облік переведень співробітників розробки: хто, з якого проєкту, на який, з якою часткою
зайнятості й з якої дати. Журнал, зріз на будь-яку дату, звіт по місяцях у Excel,
довідники, заливка людей із вигрузки HR-системи й табель відсотків залученості по командах.

Next.js (App Router) + Redis. Розрахований на Vercel.

---

## Ролі й доступ

У кожного користувача свій логін і пароль. Ім'я та роль людина на вході не обирає:
їх бере сервер із її облікового запису під час кожного запиту.

| Роль | Що бачить | Що може |
|---|---|---|
| **Адміністратор** | увесь застосунок | усе: переведення, довідники, команди, звіти, **місяць для фін. обліку**, **користувачі й ролі** |
| **HRD** | людей, проєкти, усі переведення, зріз і звіт; з команд — лише свої | створювати переведення від свого імені, правити й скасовувати **свої**; вести табель і подавати період своїх команд. Не може: видаляти записи, погоджувати за PM, змінювати довідники, команди, налаштування й користувачів |
| **Відповідальний** | лише команди, де його ім'я стоїть у полі «Відповідальний за %» | вносити відсотки своїх людей, переносити з попереднього періоду, подавати період, вивантажувати звіт своєї команди в Excel |

Права перевіряє сервер, а не лише інтерфейс:

- `/api/state` відповідає адміністратору (усе) та HRD (без чужих команд і табелів; правки перевіряються: лише свої переведення, лише свої команди, без видалень, довідників і налаштувань), відповідальні отримують 403;
- `/api/team` віддає відповідальному лише його команди й людей цих команд, без переведень, журналу, PM та інших команд;
- записати відсотки можна тільки для людей своєї команди й тільки в період, який ще не подано;
- відкрити поданий період знову може лише адміністратор;
- паролі зберігаються як scrypt-хеш окремим ключем і ніколи не потрапляють у `/api/state`;
- після 8 невдалих спроб логін блокується на 15 хвилин;
- видалення користувача, зміна ролі чи скидання пароля діють одразу, навіть для вже відкритих сесій.

**Як відповідальний потрапляє до своєї команди.** Сервер порівнює ім'я з облікового запису
(«Довідник → Користувачі») з полем «Відповідальний за %» команди («Довідник → Налаштування»).
Регістр і пробіли по краях не мають значення, решта має збігатися буква в букву.
Одна людина може відповідати за кілька команд: у неї з'явиться перемикач.

## Розгортання

### 1. Проєкт у Vercel і сховище

На vercel.com → **Add New → Project** → оберіть репозиторій → **Deploy**.
Далі **Storage → Create Database → Upstash for Redis → Connect**: Vercel сам додасть
`KV_REST_API_URL` і `KV_REST_API_TOKEN`.

### 2. Перші облікові записи (один раз)

1. Vercel → **Settings → Environment Variables** → додайте `SETUP_TOKEN`:
   будь-який довгий випадковий рядок (від 16 символів). Потім **Redeploy**.
2. Відкрийте `https://<ваш-домен>/setup`, вставте `SETUP_TOKEN` і натисніть «Створити облікові записи».
3. Сторінка **один раз** покаже логіни й паролі:

| Ім'я | Логін | Роль |
|---|---|---|
| Богдан Білоус | `bohdan.bilous` | адміністратор |
| Марія Литвин | `mariia.lytvyn` | адміністратор |
| Тарас Мамай | `taras.mamai` | відповідальний |
| Станіслав Стояцький | `stanislav.stoiatskyi` | відповідальний |
| Христина Чепурна | `khrystyna.chepurna` | відповідальний |
| Тарас Грищук | `taras.hryshchuk` | відповідальний |
| Галина Никончук | `halyna.nykonchuk` | відповідальний |
| Євгеній Кулик | `yevhenii.kulyk` | відповідальний |

   Збережіть таблицю й передайте кожному його пару особисто.
4. Після цього `/setup` більше не працює. `SETUP_TOKEN` можна прибрати з Vercel.

Далі людей додає, видаляє, перейменовує й призначає роль (відповідальний / HRD / адміністратор) адміністратор
у **«Довідник → Користувачі»**. Там же скидається пароль: новий показується один раз.

### 3. Прив'язати відповідальних до команд

«Довідник → Налаштування → Команди і відповідальні»: у полі «Відповідальний за %»
впишіть ім'я точно так, як у «Користувачах». Людей до команди прикріплюють
на вкладці «Команди і теги» або колонкою «Команда» в довіднику співробітників.

### 4. Залити людей

«Довідник → Співробітники → Обрати файл» або перетягніть Excel/CSV у поле заливки.
Колонки розпізнаються за шапкою: ім'я одним стовпчиком або пара «Ім'я» + «Прізвище»,
а також ідентифікатор, посада, проєкт і відсоток.

### Змінні середовища

| Змінна | Потрібна | Для чого |
|---|---|---|
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | так | Redis; Vercel додає сам |
| `SETUP_TOKEN` | лише для першого запуску | код для сторінки `/setup` |
| `FORM_SECRET` | для Google Форми | спільний секрет із властивістю скрипту форми (від 16 символів) |
| `APP_SECRET` | ні | ключ підпису сесій; якщо не задано, використовується `KV_REST_API_TOKEN`. Якщо змінити ключ, усі сесії завершаться. |

`APP_PASSWORDS`, `APP_PASSWORD`, `NEXT_PUBLIC_GOOGLE_CLIENT_ID` і `NEXT_PUBLIC_ALLOWED_DOMAIN`
більше не використовуються: спільний пароль дозволяв увійти під будь-яким ім'ям. Їх можна видалити.

## Локальний запуск

```bash
npm install
cp .env.example .env.local   # задайте SETUP_TOKEN; Redis можна лишити порожнім
npm run dev                  # далі http://localhost:3000/setup
```

Без змінних Redis сервер тримає дані в пам'яті процесу, тож після перезапуску все зникне,
і `/setup` доведеться пройти знову. Для локальної перевірки цього досить, на Vercel — ні.

## Що всередині

```
app/page.jsx                    сторінка
app/setup/page.jsx              одноразове створення перших облікових записів
app/api/login/route.js          вхід: логін + пароль → підписаний токен
app/api/state/route.js          GET/PUT стану (адміністратор — усе, HRD — з перевіркою прав)
app/api/team/route.js           GET/PUT табеля своїх команд (відповідальний)
app/api/admin/users/route.js    керування користувачами (лише адміністратор)
app/api/setup/route.js          створення перших облікових записів
app/api/requests/route.js       заявки з Google Форми (секрет) і їхні статуси (адміністратор)
components/TransferDesk.jsx     інтерфейс адміністратора й HRD + вкладка «Користувачі»
components/TeamDesk.jsx         інтерфейс відповідального
lib/users.js                    облікові записи, паролі, токени
lib/auth.js                     хто робить запит
lib/merge.js                    злиття станів (спільне для клієнта й сервера)
lib/hours.js                    перерахунок годин у відсотки (спільне)
lib/store.js                    Redis або пам'ять
lib/api.js                      клієнт до /api/state
```

**Як зберігаються дані.** Стан застосунку — один JSON: співробітники, проєкти, переведення,
довідники, команди, табель, журнал дій. Адміністратор надсилає свою копію, сервер зливає її
зі збереженою за `id` і часом останньої правки, тож паралельна робота не губить чужих записів.
Відповідальні пишуть лише рядки табеля своїх людей через `/api/team`.
Облікові записи лежать окремим ключем `transfers:users:v1`.

**Заявки з Google Форми** (вкладка «Заявки», лише адміністратор). PM заповнюють Google Форму без логінів
у застосунку; скрипт форми (Apps Script, файл `google-form-script.gs`) надсилає кожну відповідь на `/api/requests`
із секретом `FORM_SECRET` і щоранку оновлює у формі списки людей, проєктів і підстав. «Створити переведення»
підставляє заявку у форму нового переведення; після збереження заявка позначається як оброблена й пов'язується
з переведенням (`requestId`). Заявки лежать окремим ключем `transfers:requests:v1`.

**Години замість відсотків.** У табелі кожної команди є перемикач «% / години» (у відповідального,
HRD і адміністратора). У режимі годин відсоток проєкту = його години ÷ усі години людини за період,
з округленням до цілих так, що сума — рівно 100. Години зберігаються в рядку табеля (`hours`) і
потрапляють у вивантаження; відсотки з годин перераховує сервер, тож підробити їх не вийде.
Якщо рядок потім змінити у відсотках, години для нього скидаються. Максимум — 744 год за період.

**Місяць для фін. обліку** (вкладка «Місяць · фін. облік», лише адміністратор). Дві половини табеля
зводяться в один місяць пропорційно дням: `01–15 × 15/N + 16–N × (N−15)/N`, де N — днів у місяці,
з округленням до цілих так, що сума лишається 100. Якщо одну половину не заповнено, береться інша
(рядок позначається «бракує …»). Будь-яку клітинку можна змінити вручну: вона підсвічується,
розрахунок видно в підказці, «скинути» повертає його; поруч — примітка, чому змінено.
«Закрити місяць» фіксує цифри й теги знімком: подальші правки табеля на них не впливають
(вкладка попередить, що табель змінився). Відкрити місяць знову може адміністратор.
«Звіт в Excel» дає аркуші: місяць по людях (обидві половини, розподіл, тег, тег за розрахунком,
джерело, примітка), ставки по проєктах і по кодах, список коригувань і статус подання періодів.
Дані лежать у стані під ключем `fin`; HRD і відповідальні їх не бачать і не змінюють.

**Погодження PM.** Кожному проєкту призначається PM. Переведення діє з дати незалежно від
погодження, PM підтверджують уже доконане. Режим «хто віддає» чи «обидві сторони»
вмикається в «Довідник → Налаштування».

**Чого немає.** Історії версій записів (зберігається лише хто і коли востаннє змінив),
сповіщень, ролі «тільки перегляд». Стан лежить одним ключем — це просто й швидко
до кількох тисяч переведень; далі варто розкласти по таблицях у Postgres.
