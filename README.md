# Переведення між проєктами

Облік переведень співробітників розробки: хто, з якого проєкту, на який, з якою часткою
зайнятості й з якої дати. Журнал, зріз на будь-яку дату, звіт по місяцях у Excel,
довідники та заливка людей із вигрузки HR-системи.

Next.js (App Router) + Redis. Розрахований на Vercel.

---

## Розгортання за 15 хвилин

### 1. Покласти код у репозиторій

```bash
cd perevedennya
git init && git add -A && git commit -m "Переведення між проєктами"
gh repo create perevedennya --private --source=. --push   # або створіть репозиторій руками
```

### 2. Створити проєкт у Vercel

На vercel.com → **Add New → Project** → оберіть репозиторій → **Deploy**.
Next.js визначиться сам, нічого налаштовувати не треба. Перший деплой підніметься
з попередженням, що сховище не підключене — це нормально, виправимо на кроці 3.

Або з термінала:

```bash
npm i -g vercel
vercel        # прев'ю
vercel --prod # прод
```

### 3. Підключити сховище

У проєкті на Vercel → вкладка **Storage** → **Create Database** → **Upstash for Redis**
→ **Connect**. Vercel сам додасть змінні `KV_REST_API_URL` і `KV_REST_API_TOKEN`.
Безкоштовного тарифу вистачає з великим запасом: увесь стан — це один ключ на кілька сотень кілобайт.

### 4. Увімкнути вхід через Google

1. Google Cloud Console → **APIs & Services → Credentials → Create credentials →
   OAuth client ID → Web application**.
2. **Authorized JavaScript origins**: адреса застосунку, напр. `https://perevedennya.vercel.app`
   (і `http://localhost:3000` для локальної роботи). Redirect URI не потрібен.
3. У Vercel → **Settings → Environment Variables** додайте:

   | Змінна | Значення |
   |---|---|
   | `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | client ID з кроку 1 |
   | `NEXT_PUBLIC_ALLOWED_DOMAIN` | домен Workspace, напр. `checkbox.ua` — пускатиме лише свої акаунти |

4. **Redeploy** (змінні `NEXT_PUBLIC_*` вшиваються під час збірки).

Перший, хто увійде, стає адміністратором. Далі ролі роздаються у «Довіднику → People Partners».

### 5. Залити людей

«Довідник → Співробітники → Обрати файл» або перетягніть Excel/CSV у поле заливки.
Колонки розпізнаються за шапкою: ім'я одним стовпчиком або пара «Ім'я» + «Прізвище»,
а також ідентифікатор, посада, проєкт і відсоток. Якщо стовпчика з проєктом немає,
застосунок запитає, з якої колонки його взяти.

---

## Локальний запуск

```bash
npm install
cp .env.example .env.local   # заповніть client ID; Redis можна лишити порожнім
npm run dev
```

Без `NEXT_PUBLIC_GOOGLE_CLIENT_ID` API відповідатиме 401. Щоб покрутити застосунок
без Google, додайте в `.env.local` рядок `ALLOW_INSECURE_LOGIN=1` — вхід буде за іменем.
**На проді цього робити не можна**: будь-хто зможе назватися ким завгодно.

Без змінних Redis сервер тримає стан у пам'яті процесу. Для локальної перевірки годиться,
на Vercel — ні: кожен запит може потрапити в інший інстанс.

## Що всередині

```
app/page.jsx              сторінка
app/api/state/route.js    GET/PUT стану, перевірка токена і прав
components/TransferDesk.jsx  весь інтерфейс
lib/merge.js              злиття станів (спільне для клієнта й сервера)
lib/auth.js               перевірка Google id_token
lib/store.js              Redis або пам'ять
lib/api.js                клієнт до API
```

**Як зберігаються дані.** Увесь стан — один JSON: співробітники, проєкти, переведення,
довідники, ролі, журнал дій. Клієнт надсилає свою копію, сервер зливає її зі збереженою
і повертає результат. Записи звіряються за `id` і часом останньої правки, видалене
позначається «надгробком», щоб не воскресало під час злиття. Тож паралельна робота
двох People Partners не призводить до втрати чужих записів. Якщо двоє правлять
**той самий** запис одночасно — виграє пізніша правка.

**Погодження PM.** У довіднику проєктів кожному проєкту призначається PM. Переведення
діє з дати незалежно від погодження — PM підтверджують уже доконане. Погодження збираються
з проєктів, яких торкнулася зміна: хто віддає частку людини і хто приймає. За замовчуванням
обов'язкове слово того, хто віддає; у «Довідник → Налаштування» вмикається режим «обидві сторони».
Підписати «погоджено» може лише PM того проєкту — сервер це перевіряє.

**Права.** Перевіряються на сервері, а не лише в інтерфейсі: створювати переведення можна
тільки від свого імені, правити й видаляти — тільки свої. Адміністратор може все,
включно з довідниками й ролями. Спроба обійти інтерфейс повертає 403.

**Чого немає.** Історії версій записів (зберігається лише хто і коли востаннє змінив),
сповіщень, ролі «тільки перегляд». Стан лежить одним ключем — це просто й швидко
до кількох тисяч переведень; далі варто розкласти по таблицях у Postgres.
